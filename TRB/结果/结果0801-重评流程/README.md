## 一、要同步的代码：**`代码/` 一个字都不用动**

2026-08-01 这一轮我改的全部文件里，**没有任何一个在 `代码/` 下**。
所以那台集中了全部产物的机器，`代码/` 保持原样即可 —— 脚本第 0 步会自己验：

    本机 TRAIN 指纹 == 198d2c8a61c8f8ba

对得上就说明评估代码与训出这批存档时**逐字相同**；对不上就别往下跑。

**只需要把这一个目录传过去**（就是本目录）：

    TRB/结果/结果0801-重评流程/     →   /root/trb/结果/结果0801-重评流程/

出表、统计、出图**不必在服务器上做** —— 服务器只跑重评、产出 JSON，
回传之后在仓库这边出表出图（那边有 matplotlib，且已验证图 2–5 逐像素可复现）。
这样服务器上要装的东西最少、要同步的代码最少。

> 参考：`04:147-148` 也是这个分工 —— 训练机只要 `代码/` + `balanced_pool/` + `scenarios/`，

## 四、🔴 为什么第 0.5 步的「重名检查」在这次特别重要

以前产物分散在多台机器上；这次**全部并到了一台**。而：

- `select_best_ckpt.py:_runs()` 把结果存进 `out[os.path.basename(base)]` ——
  **按文件名建字典、不去重、不告警**，同名文件分处两个目录时**静默保留后扫到的那个**；
- `run_reeval_all.sh` 闸门 0 找存档用 `find ... -print -quit` —— **第一个命中就返回**。

`03` L243-续19 C 记过的孤儿档（`rrS9` / `baseS8` / `rrS8` / `abGS8` 在克隆 C 留了半截、
完整结果在 B/D 机；`rrS0` 的旧档在 A 机）如果跟着一起搬过来了，就正好构成同名多份。
搞反一次，某条结果臂就用了**半截训练**的模型，而表面上一切正常。

体检脚本第 ⑧ 项也查这个（硬伤级），脚本第 0.5 步再单独打一遍、把重复的路径逐条列出来，
方便直接判断该留哪个（**留段数多的那个**，把另一个移走别删）。

## 五、🔴 BUDGET_SEG 怎么定

体检最后一行会打「BUDGET_SEG 上限 = N 段」= **所有 run 都达到的最小段数**（`04:220` 的规矩）。
本批 71 条满 20 段、disc 有一颗种子 19 段 ⟹ 预计打出 **19**。

- 用 19：所有臂在同一个候选窗口里挑最佳存档，**严格同预算**，报数写 19 × 507,904 = 9,650,176 步；
- 不设（用全部段）：71 条从 20 个候选里挑、1 条从 19 个里挑，选择偏倚略有不对称。

**建议按体检给的值来**（这是手册写死的规矩）。定下来之后正文里的预算数字要跟着改，回传后一并处理。
