## §0 三件实测事实（先摆事实，再谈方案）

### 事实 1 —— 官方大集训练**反而更快**（这条推翻了"大集更贵"的直觉）

从各 run 的 jsonl 里读 `train_s`（纯训练秒数，不含评估），**3 路并发实测**：

| 臂 | 训练集 | 5M 步耗时 | fps |
|---|---|---|---|
| 连续（我们的配方） | **官方 1300** | **3.70 / 3.83 h** | 363~375 |
| 连续（我们的配方） | 小集 94 | 5.14 / 5.24 h | 265~270 |
| Discrete-safe（对标） | 小集 94 | 5.82 h | 239 |
| Base（离散无盾） | 小集 94 | 3.01 h | 462 |

⟹ 换官方大集，**每步反而便宜约 27%**（场景更杂 ⟹ 每局更短 ⟹ 同步数更快跑完）。
**"上官方大集 = 更贵"这个担心不成立**，贵的只是"要多跑步数"。

### 事实 2 —— 🔴 **加步数 = 从头重训，不能"接着练"**

`run_step4e.py:1112` 的 `config_sig` **包含 `total_steps`**，注释写死"Layer-2 续训用作匹配（白名单全等·**任一不符从 0**）"。
⟹ 拿 5M 的存档想练到 10M，会**直接从 0 重来**。
唯一能"接着练"的是**热启动**（`STEP4E_WARMSTART_CKPT`），但那是另一条叙事（两段式），
而我们刚在 `03` L232-E 把热启动那条腿**砍掉**、改成"从零一次端到端"。
⟹ **要更多步数，就得按目标步数从零训一次。** 预算必须按全额算，别指望增量。

### 事实 3 —— 指标只缺一个，而且**不用重训就能补**

已经在记的（每局算、按会遇类型分型、可回溯）：

| 类别 | 具体 |
|---|---|
| 主指标 | 到达率 · 碰撞率 · 违规/局（**让路/直航已拆开**）· 紧急步% |
| 合规细节 | 六个态势（无冲突/直航/对遇/交叉/追越/紧急）的步数分布 · 让路对数 |
| 控制质量 | 转艏增量（总/让路步/其他步分开）· 油门增量 · jerk · 控制努力 · 次网格细调率 · 速度反转次数 |
| 安全裕度 | CPA 中心距 / 净空 / 发生时刻 · 最近点航向误差 · 最近点速度 · 最大速度 |
| 盾的行为 | 盾介入步数 · 兜底触发% · 投影修正量（均值 / p95 / 最大 / **零修正比例**）|
| 效率 | 路径长 · 每局时长 · 最小目标距 |
| 分型 | **按会遇类型（对遇/交叉）拆全部指标** ✅ · **失败原因旗**（超时/出界/停住/碰撞/到达）✅ |
| 过程 | 每 50 万步的训练期曲线 ✅ · 指定场景的完整轨迹 ✅ |

🔴 **缺的只有一个：单步求解耗时（实时性）**。审稿人几乎必问"这个投影 QP 能不能实时跑"。
✅ **但它是评估期指标** ⟹ **拿现成存档补测即可，不用重训**。

> 🟢 **这条能极大缓解"一次就要弄出来"的焦虑**：
> **只要存档在，任何评估期指标都能事后补**（重评一遍即可，1~2 小时）。
> 真正"错过就没了"的只有**训练期过程量**，而那个我们记得很全；
> 且 `STEP4E_KEEP_SEGMENTS=1` 打开后**每一段的存档都留着** ⟹ 连"训练中途某个时刻长什么样"都能事后重放。
> **所以真正一次定死、不可返工的，只有：训练集 / 步数 / 臂集合 / 种子数 这四样。**

## §1 要拍板的四件事（其余都可事后补）

### 决策 1 · 训练集：官方 1300 还是小集 94？

| | 小集 `manifest_hocr_200`（94 训练场景）| **官方 `manifest_official_1300`** |
|---|---|---|
| 现状 | 现有 56 条臂全在这上面 | 只有 3 颗种子的探针 |
| 审稿风险 | 🔴 **"你只训了 94 个场景？"** —— 最可能被问的一条 | 🟢 标准做法，问题直接消失 |
| 训练/测试分布 | 对遇:交叉 = 1:1（人工配平）| **36%:64%，与官方测试集一致** 🟢 |
| 每步成本 | 1.03 h/百万步 | **0.76 h/百万步**（更便宜）|
| 需要的步数 | 5M 已基本够（10 颗里 3 颗还在爬）| 🔴 **未知**，5M 时 3/3 都还在爬 |
| 代价 | 0（已有）| **全部臂重训** |

**我的推荐：上官方 1300**（与 user 直觉一致），三条理由：
1. 训练/测试分布**本来就该一致**，这不只是"看着规范"，是方法论上更对；
2. 每步更便宜，成本劣势没有想象中大；
3. "只训 94 个场景"是本项目**最容易被一击致命**的地方，而防守论证（"对照臂同集所以公平"）
   只能挡住一半 —— 挡不住"你的绝对数字有没有意义"。

⚠️ **但有个硬前提**：得先知道**要多少步**。见决策 2。

### 决策 2 · 步数：5M / 8M / 10M / 更多？

已知：官方 1300 在 5M 时**三颗种子全部还在明显上升**（`03` L238），s3 甚至到第 6 段才爬出崩塌吸引子。
⟹ **5M 明确不够**。但到底 8M 够不够、10M 够不够，**现在没有任何数据能回答**。

🔴 **纯靠猜会付出很大代价**：全量约 50~80 小时，猜错就是全废。

**⟹ 我的强烈建议：先跑一个 8 小时的"步数试探"，再定全量。**

```
试探：官方 1300 · 我们的配方 · 从零 10M · 3 颗种子（1/3/4，与现有探针同种子可纵向对照）
成本：10M × 0.76 h/M ≈ 7.6 h/run，3 路并发 ⟹ 约 8 小时（一个晚上）
```

**关键：这 8 小时不是白花的** ——
- 判据**事先定死**：中位曲线末 3 段的提升 < 2 个标准误 ⟹ 10M 够；否则不够，拿曲线外推再谈；
- 若 10M 够，**这 3 颗种子直接就是最终那 10 颗里的 3 颗**（配方/步数完全一致）⟹ 等于预付款；
- 分段存档现在是打开的 ⟹ 顺带拿到每 50 万步的存档，"最好存档 vs 末段存档"那个口径问题也能一并回答。

### 决策 3 · 臂集合与种子数（**这个最贵，直接决定总时长**）

| 臂 | 作用 | 建议种子数 |
|---|---|---|
| **Ours**（我们的配方）| 主角 | **10** |
| **Discrete-safe**（对标论文）| 唯一的正面对手 | **10**（现在只有 5·n 不齐审稿人会问）|
| Base（离散无盾）| 上界参照 + "软奖励无效"的分母 | 5 |
| Rule-reward（离散软奖励）| 钉死"软奖励换不来合规" | 5 |
| **连续·无盾** | 🔴 **目前完全没有** ⟹ 盾的价值无法在连续臂上干净归因 | 5 |
| 金标（两个开关都不开）| 消融的"都不改"格 | 5 |
| A（只 Beta）| 消融 | 5 |
| B（只改状态机）| 消融 | 5 |

**方案甲（全套·50 run）**：上面全部搬到官方 1300。
**方案乙（省一半·35 run）**：**消融三臂（金标/A/B）留在小集**，只把"钱图那五条臂"搬到官方 1300。
  诚实交代："消融为控制算力在较小的精选集上做，主对比用官方划分" —— 常见且可接受，但不如全套硬。

### 决策 4 · 存档口径：末段存档 vs 最好存档

`03` L236-B：46 条臂里只有对标论文的 s0 出现"练到 100% 又崩回 5%"，而我们评末段 = 评到它最差时刻。
现在分段存档已打开 ⟹ **正式实验里这个口径可以自由选，但必须对所有臂统一**。

| 选项 | 说明 |
|---|---|
| **甲：末段存档**（现状）| 最保守、无选择偏倚；但对"末段崩溃"的臂单方向不利 ⟹ 必须报灵敏度 |
| 乙：**验证集最优存档** | 正统做法（官方 1400 里切出的 100 个验证场景选，**绝不碰测试 600**）；对所有臂统一施加 |

**我的推荐：乙。** 理由：官方大集本来就切了 100 个验证场景（现成的、且与测试集零交集），
用验证集选存档是教科书做法、审稿人不会问；而甲需要额外解释一颗种子的崩溃。
⚠️ 无论选哪个，**必须对所有臂统一**，且在论文里写死。
