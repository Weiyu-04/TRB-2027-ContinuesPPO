## §8 必须写进论文的诚实口径（不是可选项）

1. **训练预算标注**：所有表标注「10M 步预算 · 验证集选最佳存档 · 官方测试集」。
   若到期仍未收敛（`03` L238 已见先例），只能写「该预算下尚未收敛」，**绝不能写「大数据集效果更差」**。
2. **崩种子污染**：凡逐局平均的指标同时报「全部种子 / 仅练成的种子」两版。
3. **盾的倍数用单变量版**：同为离散、只差有没有盾（`03` L234-E⑤）。跨动作空间那版只能说「我们这一套比无盾基线安全 N 倍」。
4. **碰撞如实报**，写「与对标统计上无差异（Fisher p=…）、二者均远低于无盾基线」，**绝不写「零碰撞」**。
5. **可证明层守 `CLAUDE.md` §0 诚实档**：能严证 = 远场单步无碰 + 每让路步方向合规 + 紧急迫近不可避 sound 证书；**绝不写 provably collision-free / provably compliant（裸）**。命题 4 仍 PROVISIONAL。
6. **COLREGs 覆盖边界**：R17(a)(ii)/(b)/(c)、R18、R19、R9、R10 未实现（对标论文同样没做·范围一致）；**官方库无追越场景**。
7. **探索期结果若引用（如"小集上跑过 10 颗种子"），必须标明是另一套口径**（见 §4）。
8. 🔴 **转艏平顺度不能写成"我们赢了离散臂"**：我们的连续臂训练时开着 `r_rate`，罚的**正是**上报的
   「转艏增量」这个量，而离散臂结构上拿不到这一项（`reeval_official.py:561` 早已立此红线）。
   ✅ 正确写法 = **消融口径**："同样开着该罚项，无界高斯 → 有界 Beta，转艏增量降到 N 分之一
   ⟹ 改善来自**有界动作分布**，不来自额外奖励项"。跨臂只能写"我们这一套比基线平顺 N 倍"。
   同理 `PARK_W=20`（终端保速势）帮到达率，离散臂也没有 ⟹ 一并披露。
   🔴 **数字必须取自 ⑦ab0 ↔ ⑧abB 的同种子配对**，且**按 §8-2 两版都报**（全部种子 / 仅练成的种子）。
   〔2026-07-29 复审订正：此处原引 `0.01472 → 0.00403`，① 那是**探索期小集 563 口径**、正式表里不得出现；
   ② 它**只报了一版**，与 §8-2 自己的规矩冲突 —— 那条臂 5 颗种子里 s6 是崩种子（到达 0.36%、
   转艏 0.00977 ≈ 其余的 4 倍）⟹ 全部种子 3.65× vs **仅练成 5.60×**，**报的偏偏是对我们不利的那版**。〕
9. 🔴 **不得暗示我们比几何控制器（CBF/VO/PD）平顺**：实测 CBF 最优配置 jerk 0.165 / 转艏 0.00231，
   我们 0.196 / 0.00256 —— **基本打平，略输**。正确说法："我们学出来的策略平顺度**与手工调参的几何控制器相当**，
   同时到达率高 22 点、违规低 9 倍"。这比"我们最平顺"稳得多。
10. **外部基线的到达率必须带限定**：它们位置命中 97~99.6%，卡在终端**朝向门 ±9.74°** 外（朝向误差 15~32°）；
    几何控制器的标称律不含终端对准环节 ⟹ 那一列反映的是终端约束类型差异，不是避碰能力。
11. **外部基线的违规数受回合长度影响**：它们未到达局精确跑满 170 步，我们约 80 步，而直航违规是逐步累计的
    ⟹ 必须同时报"每局"和"每步"两版。

〔以下三条为 2026-07-29 复审提出、**user 已拍板并入**（`03` L243-改④⑤）〕

12. **"盾在连续动作空间值多少"这个数带硬限定**：⑤⑥ 那对孪生臂用的是**无界高斯**
    （`run_step4e.py:232` 的守卫不许 `beta` 与无盾同开），而该分布下实测 **76~84% 的步在动作箱外、贴边 73%**
    ⟹ 这个倍数是**在连续动作最差的形态下**测得的。**必须与数字同处出现**，不能只写在 §3。
    同理 ③↔⑤ 的"离散换连续本身值多少"很可能是**负的** —— 那是诚实的下界，照写。
13. **同机同趟纪律 + 抖动量级**：一张报数表里每条臂必须同一台机器、同一趟评；
    跨机/跨趟连续臂最大差 **约 1.6 个百分点**（`03` L234-H；离散臂逐位一致）。**禁止再写"±0.5pt"。**
14. **"练成的种子数"这一列必须附判据定义**：练成 = strict 到达 ≥50%；
    崩（打转吸引子）= 到达 <50% **且**末段每局时长 ≥ **1360 秒**（= 0.8 × 回合上限 170 步 × 10 秒）；
    欠训 = 到达 <50% 且末段每局时长 < 1360 秒。**并报过渡带（1100~1600 秒）的条数** —— 那一带标签本身是灰的。
    （全库 100 条低到达 run 实证：崩组 [1377,1700] / 欠训组 [567,1354]，阈值处不重叠 · 12% 落在过渡带。）

15. **单步求解耗时（实时性）的口径**：是**单线程 CPU 墙钟**，随机器而变 ⟹ 必须连**机器型号 + 线程设置**
    一起写；看**尾部（p95/p99）不看均值**；**别写成"比某某快 N 倍"**（要同机同口径才成立）。
    他船不在窗内的步盾会短路、不解 QP ⟹ 那些步**不计入**求解耗时分布（否则一堆 0 把 p99 冲淡）。
    量法：`代码/tests/measure_solve_time.py`（**不碰生产代码**，B 类量、事后补测即可）。
16. **轨迹对比图（Fig.4）的选场景规则**：`PASS=traj` 那一趟把**全部 600 个测试场景**的轨迹都采了
